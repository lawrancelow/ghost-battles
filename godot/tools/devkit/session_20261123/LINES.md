## 測試（重要：機器只有 2 核，多條線共用）
- 單項：bash /home/claude/setup/edtest.sh /home/claude/wt/<線名>/godot <唯一tag> res://tools/tests/<x>.gd <func> <秒>
  - 已經自動排隊（flock /tmp/gbtest.flock），多線同時叫會輪候，不會互殺。
- 任何其他要開 Godot / xvfb-run 的指令，一律包在：bash /home/claude/setup/gbrun.sh <指令...>
- 絕對不要跑 run_all_suites.sh、st16.sh、update_test.sh、mkpatch.sh（整合由總指揮做）。
- 絕對不要 pkill godot / pkill Xvfb（會殺別線）。
- 寫新測試放 res://tools/tests/<線名>_test.gd，照現有測試寫法（看 namefix_test.gd、zone_test.gd）。輸出 "[tag] RESULT ok=N bad=M"。
- 改過的地方，相關舊測試要跑過不能壞（例如 zone_test、village、unify、mapbattle_test、pace_test）。

## 熱更新硬限制
- 不可以新增 class_name、autoload，不可以改 project.godot。新腳本用 preload("res://...") 引用。

## 合併衝突少啲
- 新功能盡量寫在新檔案；改舊檔案只加最少的掛鈎（hook）幾行，並在旁邊加註解 `# [線名]`。
- 存檔新欄位：讀的時候一律用 .get(key, 預設)，舊存檔直接能用。
- 共用約定（各線照住寫，整合時會接駁）：
  - 行動目標登記（ctl 線建立 res://game/outpost/act_targets.gd）：
    `const AT = preload("res://game/outpost/act_targets.gd")`；`AT.providers` 是靜態 Array of Callable，每個 Callable 傳入 game 節點、回傳 Array[Dictionary]，每個目標：
    {id:String, kind:"stage"/"king"/"res"/"landmark"/"barracks"/"raid", name:String, pos:Vector2(村地圖座標), my_pow:int, foe_pow:int(0=非戰鬥), icon:String(可空), go:Callable}
    其他線（landmark、barracks、raid）如果 ctl 未合併，自己的 worktree 裡先建立同名檔案的最小版本（只有 `static var providers := []`），整合時以 ctl 版為準。
  - 陰兵派遣存檔（barracks 線擁有）：S.army = {def:int, sweep:{zone_id:int}, cap_def:Array[鬼id], cap_sweep:{zone_id:鬼id}}。raid 線只讀：防衛戰力 = S.army.def 和 cap_def，讀法要容許欄位不存在。
- 新劇情／對白：港式粵語原句＋中文，女主版本經 DB.N；守「一個任務只放一段故事」（mv_story.gd 規則）。
